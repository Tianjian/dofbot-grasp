# DOFBOT SE 手腕相机抓取：真机部署全流程

目标：**手腕 USB 相机看到 30 mm 立方体木块 → 本机算力算出关节角 → 串口下发 5 个舵机 + 夹爪 → 抓起并验证。**

仿真侧已用 roboharness 验证（`harness/run_wedge.py`：抬起 106 mm、4 个指-块接触、gate exit 0；夹爪不闭合的故障注入 gate exit 1）。

本文是**真机落地**的步骤、参数、判据与回退方案。所有硬件事实来自 `analysis/prior-projects.md`（逐行引用 `Arm_Lib.py`），标注 `[待实测]` 的项必须在真机上一次量出来再写死。

---

## 0. 总体架构（与仿真一一对应）

```
        ┌──────────────────────────── 本机（CPU 即可）────────────────────────────┐
USB ──► │ camera.UsbCamera  → perception.detect_cube → 30mm 立方体 bbox/距离      │
相机     │        │                                                                │
        │        ▼                                                                │
        │ pipeline.GraspPipeline（home→search→align→approach→grasp→lift→verify）  │
        │        │ 目标 TCP 位姿                                                    │
        │        ▼                                                                │
        │ kinematics.inverse（DLS，带限位）→ 关节角 rad → 舵机角 u_deg              │
        └────────┼────────────────────────────────────────────────────────────────┘
                 ▼
         bus.SerialBus（115200，Arm_Lib 兼容帧）──► 桌面机器人 6 舵机
```

仿真与真机**共用** `kinematics / perception / pipeline`，只有 `camera`、`bus` 两个实现不同。因此仿真里验证过的状态机与阈值，可以直接搬到真机。

## 1. 台面安全（先做，不要跳）

1. **供电与限流**：先用可调电源限流到 `[待实测]`（建议从 2 A 起），防止舵机堵转烧毁。
2. **E-stop**：手边能随时断电；软件侧加 `Ctrl-C` 立即停止发送（不要发送"回零"，断电更安全）。
3. **首次上电不要装夹爪**，空载验证方向。
4. **逐关节 ±10° 方向校验**（这步是必须的，见 §3 的双重反向陷阱）：

   ```
   for i in 1..6:  发 i 号舵机 90° → 100° → 90°，眼睛确认关节朝预期方向转
   ```

   任一关节方向与预期相反 → **停下来改映射，不要在控制环里用负增益掩盖**。
5. **关节限位**：URDF 限位是 j1–j4 ±90°、j5 −90…180°。`[待实测]` 真机实际可达范围通常更小，把实测的软限位写进 `config.yaml`，并在 `bus.SerialBus` 里做**下发前裁剪**（不是靠舵机自保护）。
6. **桌面边界**：腕部在 j2/j3/j4 特定组合下可低于基座平面（实测可达 z ≈ −49 mm），必须加"桌面保护"：任何目标 TCP 的 z 不得低于 `桌面高度 + 5 mm`，否则拒绝执行。

## 2. 串口通信

| 项 | 值 |
|---|---|
| 波特率 | 115200 |
| 默认设备 | `/dev/myserial`（Yahboom 镜像自带的 udev 规则）；没有则 `/dev/ttyUSB*`，用 `ls -l /dev/serial/by-id/` 确认 |
| 设备地址 | 0x15（文档提到，**驱动里并未使用**） |
| 帧头 | `0xFF`，第二字节 `0xFC` |

**六舵机一次下发（19 字节）**：

```
FF FC 11 1D  v1H v1L  v2H v2L ... v6H v6L  tH tL  cs
```

- `0x11` = 长度字节，`0x1D` = 命令类型（写 6 舵机）
- `vIH/vIL` = 该舵机 PWM 值（大端）
- `tH/tL` = 运行时间 ms
- `cs = (LEN + TYPE + data) & 0xFF`（等价于 `sum(cmd[2:]) & 0xFF`；**不要**按"其余字节和 +5"理解，`Arm_Lib` 里的 `0xFF+0xFC+5 ≡ 0 (mod 256)` 只是巧合）

**PWM 映射**（写入前把角度转 PWM）：

```
S1,S2,S3,S4,S6:  pwm = 900  + 2200 * u / 180      # u ∈ [0,180]
S5:              pwm = 380  + 3320 * u / 270      # u ∈ [0,270]
```

**单舵机（9 字节）**：`FF FC 07 (10+id) posH posL tH tL cs`
**读角度请求**：`FF FC 03 (30+id) cs`，**回包第二字节是 0xFB，不是 0xFC**。

**时序**：19 字节 @115200 ≈ 1.65 ms 线上时间；真正的时间开销是 `Arm_Lib` 在写前 `time.sleep(0.012)` 与读超时 0.2 s。**串口不是瓶颈，读回才是**（6 舵机读一轮最坏 ~1.2 s）。

> 落地建议：不要直接用 `Arm_Lib` 的读路径（不重置 `self.id`、回包类型歧义、`Arm_ping_servo` 有死循环）。只复用它的**写帧构造**，读回自己实现并加超时/重试。

## 3. 舵机角度 ↔ 关节弧度（最容易错的地方）

```
q1..q4 = radians(u1..u4 - 90)
q5     = radians(u5 - 135)
夹爪 S6: 0..180（开合，方向与夹持力需实测）
```

**S5 规格本身自相矛盾**（`ANGLE_MAPPING.md`）：公式 `s-135` + 中点 135→0，与端点
0→−90 / 270→+180 不能同时成立。当前实现**采用公式+中点**，于是关节 5 经舵机只能覆盖
**−135°…+135°**；URDF 给的 +180° 会在舵机 270° 处饱和。这个必须在上台面后**重新标定**
（把 S5 转到机械零位，读实测值定义偏移），不要直接沿用任何一方的数字。

**陷阱 1：S2/S3/S4 的 180° 反向已经在 `Arm_Lib` 内部完成**（写和读都做了 `180 - d`），所以 `read(write(u)) == u`，**任何上层代码都不许再翻一次**。旧的 `threejs_server.py` 就多翻了一次，导致命令关节 2/3/4 实际转到 `-q`，而 UI 显示的是"命令值"所以看不出来。

**陷阱 2：S5 的 `+44°` 偏置**在旧仓库的 3 个文件里出现，但没有任何可追溯依据；它会把 S5 的等效范围推到 −91…+224°，**两端都超出 URDF 限位**。部署时**不要继承**这个偏置；用 §5 的标定重新确定零位。

**陷阱 3：`u` 越界**。`Arm_Lib` 只检查上界，`u = -5` 会算出 838（低于标称 900 下限）。所以限位裁剪必须在我们这层做。

## 4. 相机与感知

- 分辨率 640×480、MJPG、30 fps；`cv2.CAP_V4L2`。
- **必须锁定曝光与白平衡**（`cap.set` 的返回值要检查，旧仓库忽略了），否则木块在不同光照下阈值漂移。
- 安装：`link5` 坐标系下 `pos=(0.035, 0, 0.010)`，光轴沿 **link5 的 +Z**（即沿工具轴向下），FOV ≈ 75°。仿真就是这个配置，抓取时立方体约占画面 3%（预抓取）→ 11%（贴块）。
  > 实际支架需要保证相机与工具轴偏移 ≥ 15 mm 且不进入两指之间，否则会挡住视野。
- **内参标定**：棋盘格 9×6、方格 `[待实测]` mm，20 张以上，`cv2.calibrateCamera`，重投影误差 < 0.3 px；把 `fx, fy, cx, cy, dist` 写进 `config.yaml`。
- **测距方案二选一**：
  - **A（默认，无额外硬件）**：已知边长 30 mm → `z = fx * 0.030 / width_px`。误差 ≈ 边长测量误差比例；在 80 mm 距离、30 px 宽度下，1 px 误差 ≈ 2.7%。**够用于对准与预抓取**。
  - **B（更稳）**：桌面平面单应（棋盘/ArUco 标定桌面），把像素反投影到 z=桌面 平面，直接得到 XY；对光照与倾斜更鲁棒。建议真机先用 A 跑通，再切 B。

## 5. 手眼标定（决定成败的一步）

**方法：9 点接触法**（不需要标定板外参）

1. 在桌面铺一张纸，画 3×3 网格（间距 `[待实测]`，建议 40 mm）。
2. 手动/示教让 TCP（指尖中点）依次触碰 9 个点，每次记录：关节角 `q` 与图像中该点的像素坐标 `(u,v)`。
3. 由 `kinematics.forward(q)` 得到 9 个 TCP 三维点 `P_i`；用 `cv2.solvePnP`（或最小二乘单应 + 已知平面）拟合 **相机 → 基座** 的 `T_cam_base`。
4. **验收：残差 RMS < 3 mm**；否则检查网格点是否真的接触（笔尖误差会被直接放大）。
5. 复验：把 TCP 移到网格中心上方 50 mm，图像中心与预期投影偏差 < 10 px。

> 注意：`T_cam_base` 只在相机刚性固定时有意义。相机支架松动是这类项目最常见的退化源，**每次上电先跑一次复验**。

## 6. 抓取序列（每阶段的动作、时间、断言）

时间按真机舵机速度取 `[待实测]`；下表用仿真值 + 余量，`T` = 单段运动时间。

| # | 阶段 | 动作 | 下发 | 时长 | 断言 | 失败动作 |
|---|---|---|---|---|---|---|
| 1 | `home` | 回安全姿态（直立略前倾） | `write6` | 1500 ms | 关节角在软限位内 | 立即停止，报 `HOME_FAILED` |
| 2 | `search` | 抬到块上方 ~120 mm，张开夹爪 | `write6` | 1000 ms | 画面中检测到块（`cube_visible=1`） | 小幅扫描（±20 mm，3 次）；仍无 → `NO_TARGET` |
| 3 | `align` | 用桌面平面假设把 TCP 对准块中心正上方 80 mm | `write6` | 800 ms | 检测框中心误差 < `[待实测]` px；距离估计与规划值差 < 10 mm | 重测一次；仍超差 → `ALIGN_FAILED` |
| 4 | `approach` | 沿工具轴下降到 TCP 距块中心 4 mm | `write6` | 900 ms | 指尖未触桌（TCP z > 桌面+5 mm） | 回退 `align` |
| 5 | `grasp` | 夹爪合到夹持位（先慢后保持） | `write6` | 600 ms + 保持 300 ms | `[待实测]` 夹持后块应随手移动（用画面位移判断） | 张开重试一次；仍失败 → `GRASP_FAILED` |
| 6 | `lift` | 抬升 120 mm | `write6` | 900 ms | 画面中块随夹爪上移 ≥ 20 mm | 判定滑脱 → `SLIP` |
| 7 | `verify` | 保持 300 ms 后再拍一帧 | 只读 | 300 ms | 块仍在夹爪内且高度未回落 | 记 `DROP` |

**时序要点**：
- 每次 `write6` 后**必须等 `t + 余量`**（余量 ≥ 200 ms），因为没有任何运动完成反馈。
- 闭环只在 `align` 与 `grasp` 之后各做一次视觉确认；**不要**在每个阶段都闭环（舵机 + 串口延迟会让环路周期 > 1 s，30 mm 块经不起）。
- 视觉伺服增益参考旧项目 0.1 deg/px，但**必须重新标定单位**：1° ≈ 4.2 mm（全伸展），旧项目的 5°/步 ≈ 21 mm ≈ 块的 70%，等于 bang-bang。新实现建议：单步 ≤ 1.5°，死区 ≤ 5 px，最大迭代 5 次。

## 7. 验收测试

1. **单点重复性**：同一块位置连续抓 10 次，成功率 ≥ 10/10，`lifted_mm` 均值 ≥ 20 mm。
2. **位置泛化**：9 宫格每点 3 次，成功率 ≥ 8/9 点。
3. **失败归因**：每次失败必须落到具体阶段（`NO_TARGET / ALIGN / GRASP / SLIP`），落在 `UNKNOWN` 视为不可接受。
4. **鲁棒性（可选）**：光照变化（台灯开关）、块旋转 45°、块偏离中心 30 mm。
5. 指标与仿真对照：`lifted_mm`、`contact_count`、`cube_visible` 的口径与 `harness/run_wedge.py` 完全一致，便于 sim-real 对比。

## 8. 中止与回退

| 情况 | 判据 | 动作 |
|---|---|---|
| 串口超时/无响应 | 写后无回包或 `read` 超时 | 重试 1 次 → 停止，保持当前姿态（不要回零） |
| 关节软限位触发 | 目标角超限 | 裁剪并告警；连续 3 次 → 停止 |
| 相机丢失 | 连续 5 帧读失败 | 停止，报 `CAMERA_LOST` |
| 块不在视野 | `search` 扫描后无目标 | 停止，报 `NO_TARGET`（不要盲抓） |
| 夹持后未抬起 | `lift` 阶段高度差 < 20 mm | 张开、回 `approach`、重试 1 次 |
| 任意异常 | Python 异常 | `finally`: 停止发送、关闭串口、打印最后 20 条命令 |

## 9. 仿真与真机的差距（必须心里有数）

| 项 | 仿真 | 真机 | 对策 |
|---|---|---|---|
| 关节反馈 | 精确 qpos | 舵机读回不可靠、有惰性 | 开环执行 + 视觉确认；不依赖读回做控制 |
| 舵机动力学 | 位置伺服 + 力矩限 | 有回差、堵转、掉电下垂 | 降低速度、加保持时间、限流 |
| 夹持力 | 接触力模型 | 无传感、无标定 | 用固定夹持位 + 视觉确认是否夹住 |
| 相机支架 | 刚性 | 可能松动 | 每次上电复验 `T_cam_base` |
| 桌面高度 | 精确 z=0 | 有垫高/倾斜 | 标定桌面平面，或每次用块当基准 |
| 光照 | 恒定 | 变化大 | 锁曝光/WB + 阈值标定 + 必要时改用单应 |

## 10. 一键执行顺序（真机）

> 命令以当前 `cli.py` 的实际接口为准（只有 `sim` / `real` 两个子命令，参数 `--config`、
> `--json`、`--seed`）。§1–§5 的自检步骤目前需要**手工或用小脚本**完成，尚未内建为
> `--selftest`；不要照抄不存在的命令。

```bash
# 0) 依赖（只用本机 CPU）
pip install numpy opencv-python pyserial pyyaml

# 1) 通信自检（手工）：只动 S1 ±5°，确认能收到动作
python - <<'EOF'
from dofbot_grasp.bus import SerialBus
bus = SerialBus(port="/dev/myserial")
bus.write_joints([0,0,0,0,0], duration_s=0.8)   # 90° 全零位
EOF

# 2) 方向自检（手工）：逐关节 ±10°，眼睛确认方向
#    任一关节反向 -> 改 config 里的符号/限位，不要在控制环里用负增益

# 3) 相机自检：抓一帧、跑一次检测，确认能框住 30 mm 块
python - <<'EOF'
import cv2
from dofbot_grasp.perception import detect_cube
cap = cv2.VideoCapture(0); ok, frame = cap.read(); cap.release()
print(detect_cube(frame) if ok else "camera read failed")
EOF

# 4) 手眼标定（9 点）：当前需按 §5 手工采点 + 拟合，产出 T_cam_base 写入 config

# 5) 干跑：完整状态机，但不夹（把 grasp 夹持角设成张开角）
python -m dofbot_grasp.cli real --config config/dofbot.yaml --json

# 6) 正式抓取
python -m dofbot_grasp.cli real --config config/dofbot.yaml
```

标定与自检应当尽快固化成子命令（`selftest`/`calibrate`），本文只保证顺序与验收点。
